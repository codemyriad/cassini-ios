# WP11: Cassini format layer (CassiniCore)

Differences from Android's `core/format` that this package introduces. Each one follows the format spec where Android
is stricter or looser than it.

- **Verification gate.** Android verifies the audio only when no tag disagrees with the manifest. iOS blocks
  verification only when `CASSINI_AUDIO_OPUS_SHA256` disagrees, as SPEC.md asks ("the manifest wins"). Any other
  stale copy is a warning, so conformance vectors 007 and 017 read as `ok` on iOS and `unverified` on Android.
  Vector 011 stays `unverified` on both.
- **Stale audio says why.** A `stale-audio` document carries `audio-digest-mismatch` and/or `audio-shape-mismatch`
  in its warnings, the codes the conformance suite uses.
- **TITLE follows the manifest on every seal.** Android writes TITLE only on a fresh seal that has none, so an
  imported `TITLE=voice-memo` stays beside a different `meeting.title`, and a rename never reaches the tag until
  `retitle` runs. iOS sets the first TITLE to `meeting.title` in place on every seal (fresh or added variant) and
  drops repeats. `retitle` is ported as on Android.
- **Fresh seal drops every `CASSINI_*` tag of the source.** Sealing without a verified document (a plain, stale,
  unverified or unknown-format source) keeps only foreign comments. Android keeps old `CASSINI_TX_*` chunk sets,
  which makes the new `words` chunk names repeat.
- **Comments are decoded one at a time.** A foreign comment that is not UTF-8 is skipped with a
  `non-utf8-comment: NAME` warning, kept in `opaqueComments`, and written back byte for byte by seal, relabel and
  retitle (an undecodable TITLE is replaced when a title is written). Android rejects the whole file as
  `invalid-cassini-metadata`. A `CASSINI_*` comment that is not UTF-8 makes a file with `CASSINI_FORMAT` invalid
  metadata; without one the file is still plain audio.
- **Every copy is rebuilt on write.** Because iOS opens a file with stale summary copies as `ok`, seal, relabel and
  retitle rebuild every tag that copies the manifest (the transcript index, summary and origin mirrors, the
  `CASSINI_AUDIO_*` mirrors and each transcript's descriptor tags) in place, and refuse to ship a file that reads
  back with a `tag-manifest-disagreement`. Android rewrites only the summary and audio tags on a seal and only the
  manifest chunk set on a relabel or retitle, which it can afford because it never accepts such a source.
- **Compact word bodies.** `Transcript.json()` writes compact JSON (SPEC.md "Payload encoding"); Android
  pretty-prints. `WordBodyBudget` therefore counts compact bytes: about 150,000 words (some 16 hours of speech)
  fit, against Android's 110,000. All variants share the 8 MiB OpusTags limit, and a body at the budget encodes to
  a third of it or more, so a file holds at most two full-length variants. `WordBodyBudget.fitsHeader` checks the
  space left before a seal: `beside:` an existing document, or `sealing:` a source whose foreign tags (an imported
  file's cover art, say) a fresh seal keeps. Callers that seal long transcripts or imports (WP5, WP12) should use it.
- **Language.** `Transcript` defaults to `""` (it defaulted to `"it"`), the body omits `language` when empty, and so
  does the manifest descriptor. Android does the same for the body.
- **Byte-exact strings.** JSON keys, JSON string values and tag values compare by UTF-8 bytes; tag names fold ASCII
  case only, and the writer recognises the tags it rebuilds by the bytes of their names too. Swift's `==` treats canonically equivalent strings as equal, which Java's does not.
- **Media type is a hint.** A transcript is readable when its descriptor says `cassini.words.v1`; a different
  `payloadRef.mime` is a `transcript-mime-mismatch: ID` warning. Android marks the transcript unavailable.
- **Oversize headers.** An OpusHead or OpusTags packet over 8 MiB is `invalid-cassini-metadata`
  (`comment-header-too-large`), not plain audio.
- **Typed state.** `CassiniDocument.state` is the `DocumentState` enum (raw values are the spec's state names)
  instead of a string with a typed accessor. `readChecked` reports `unreadable` for any I/O error while reading the
  headers; Android checks only the first 36 bytes.
- **Error codes.** Warnings and transcript errors use the conformance codes where one exists
  (`duplicate-tag: NAME`, `chunk-missing: NAME`, `payload-sha256-mismatch: NAME`, `tag-manifest-disagreement: NAME`).
- **`SpeakerMerges.windows`** takes sample ranges and the budget explicitly (45 s and 1.5 s at 16 kHz by default)
  because the voice-print types live outside Core on iOS, and it visits speakers in id order.
