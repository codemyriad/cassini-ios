# WP12 — Import pipeline and portable documents

## Differences from Android

- **WAV.** Android reads WAV itself and accepts only 16-bit PCM (`Failure.WAV`, "Unsupported WAV"). iOS hands every
  container but Ogg Opus to AVFoundation, which also decodes 24-bit and float WAV, so there is no WAV rejection and no
  "Unsupported WAV" banner. A WAV is stored as `source.wav` like any other AVFoundation file.
- **Probe and sniff.** Android names an AVFoundation-style file from the MIME type `MediaExtractor` reports. iOS names
  it from the container signature in the first 64 bytes (`ImportClassifier`: WAV, AIFF/AIFC, CAF, FLAC, AMR, Ogg, MP4,
  3GP, MP3, ADTS AAC), because AVFoundation reports no MIME type. The display name's extension still wins when it is
  `[a-z0-9]{1,5}` and not `opus`, `wav` or `tmp`, as on Android.
- **Opus playback.** Android plays Ogg Opus directly. iOS cannot, so an imported plain Opus file (`source.opus`) or
  document (`document.opus`) is decoded once to `playback.caf`, which the note plays; the imported file is kept as
  `originalAudioFilename` and is what an export seals. A plain Opus file that does not decode is rejected as "Can't
  open this file". A document whose audio does not decode stays a document note with unplayable audio, so its
  transcript and trust state still show.
- **Document cache.** Android verifies a document at import and keeps a signature-keyed catalogue cache. iOS verifies it
  once at import and stores what it read in `note.json` (`DocumentInfo`: state, warnings, unavailable variants with
  their errors, and the OpusTags vendor); the file is never read again to open the note.
- **Verification.** Because iOS blocks verification only on an audio digest mismatch (WP11), vectors 007 and 017
  import as `ok`, not `unverified`; both keep their transcripts either way.
- **Unavailable default variant.** When the default transcript of a readable document does not decode, the first
  variant that does becomes the note's transcript; the others are versions, and the unavailable ones are kept by id
  with their errors.
- **Opening the note.** As on Android, a file picked in the Library is imported into the list and nothing opens; a
  file opened from another app (Files, a share, AirDrop) opens its note when the import ends, or the note that already
  has those bytes. The picker takes several files at once (Android's takes one).
- **Display names.** iOS always has a file name for an imported URL, so Android's "content Uri without a display
  name" case only applies to an empty name; it gets the fallback title "Imported audio" too.
- **Cassini or plain Opus.** As Android's `AudioFiles.isCassini`, an Ogg Opus file is a document only when a comment
  names `CASSINI_FORMAT` (`CassiniDocument.namesCassiniFormat`), and one whose headers or comments do not parse is
  "Can't open this file". Android also gives "Can't open" when the copy cannot be read back; iOS treats a read error
  on its own staging copy as a storage error (`cannotSave`, or `noSpace` on a nearly full volume).
- **Size before the download.** The size the provider reports (an iCloud placeholder reports its logical size) is
  checked against the 4 GiB cap and the free space before the coordinated read, which is what downloads a placeholder;
  the copy still enforces both when no size is reported.
- **Imports during launch.** A file opened from another app on a cold launch is held, with "Importing <name>…"
  showing, until the launch work has read the notes and the queue; Android needs no wait because its duplicate check
  queries the database.
- **Classification off the cooperative pool.** The sniff, the document verification and the Opus scans run on their
  own queue, with cancellation checked between them; a verified document's duration is the one its verification
  measured, so it is scanned only once.
- **Storage errors.** iOS has no SQLite; a failed move, decode or `note.json` write after the copy is `cannotSave`, or
  `noSpace` (with the whole file plus 64 MiB) when the volume has under 64 MiB left, as Android's SAVE and SPACE. A
  decode that fails while the volume is nearly full is `noSpace` whatever error AVFoundation gave, so a document does
  not become an unplayable note for want of space.
  Both `cannotOpen` and `cannotSave` show Android's IMPORT_OPEN copy.
- **Concurrency.** Imports run side by side (Android's `ImportTracker`); the duplicate check and the note write are one
  step on the `NoteStore` actor, as Android's `insertUnlessDuplicate`, so four imports of one file at once add one
  note.
- **Auto-transcription.** iOS keeps its "transcribe automatically" setting. An import is queued only when it brought
  no readable transcript, its audio plays, and it is not a document in a newer format.
- **Portable export.** Exports go through `PortableExportService` in CassiniEngine. Intermediate files are in
  `<export folder>/work/`, so a note titled "encoded" no longer collides with them. The audio of a note without an Ogg
  Opus original is encoded with libopus, every channel mixed down to mono (`AVAudioConverter.downmix`), and a failed
  final write of the Opus file is reported and leaves nothing. The language is written as BCP-47 (`en-US`), and an
  export that would not fit the 16 MiB word body or the 8 MiB OpusTags packet is refused (`PortableExportError.tooLong`)
  before it is written. Exporting a note imported from a stale, unverified or unknown-format document seals a fresh
  document over the same audio (WP11's seal fix), with the document's other readable variants added before the
  note's transcript; the imported file itself is never changed.
- **PortableDocumentTest.** Android's first test (`theEncoderCapabilityHasAClearOutcome`) is ported as
  `CassiniAudioTests/PortableDocumentTests`: a document written over the app's own Opus encoding reads back `ok` with
  the source's duration. Android's second test checks the platform Opus encoder of API 34; iOS has no platform Opus
  encoder in use, so it has no counterpart.

## Interfaces added or changed (for later work packages)

- `AudioProcessing.encodeOpus(_:to:)` was added to the frozen port (implemented by `LocalAudioProcessing` and
  `FakeAudioProcessing`), so the portable export can run in CassiniEngine, which does not link CassiniAudio.
- `CassiniEngine` and `CassiniEngineTesting` now list `CassiniCore` as a dependency in `Package.swift` (they read
  Ogg Opus headers and documents).
- `NoteStore.liveNote(withSourceSha256:)` and `NoteStore.insert(_:unlessLiveSourceIs:)` (extension in
  `Engine/Import/NoteStore+Import.swift`).
- `LibraryStore.adopt(_:)` shows a note another writer just saved (the import) before its change notification.
- `ImportStore` takes an `ImportService` and exposes `tracker: ImportTracker` (`running`, `failure`,
  `dismissFailure()`): WP9's `NoticeCenter` should build `NoticeFacts.importing` and `importFailure` from it and then
  replace `ImportActivity`, the interim Library view.
- `PortableTranscript` now describes any non-plain document (state, warnings, title, `createdAt`, `duration`,
  versions, `unavailableVariants`, vendor); `DocumentTrust` maps a state to Android's trust chip and banner.
  `DocumentTrustChip` and `DocumentTrustNotice` (app, `Features/Import/ImportViews.swift`) render them in the note
  header and notices; WP6 may move them into its own layout.
- `ImportStore.init` takes `ready`, which returns once launch has run (`AppGraph` passes `startup.ready()`); an import
  waits for it and is `cannotSave` when the library failed to load. `LibraryStore.load()` subscribes to changes before
  reading.
- Trust banner: `DocumentTrust.showsBanner(_:toggled:)` and `offersPlayAnyway`; the chip (`DocumentTrustChip(trust:
  toggle:)`, `NoteHeader.toggleTrust`) toggles the banner and "Play anyway" sets `document.trustAcknowledged` and
  plays, as Android. The banner and the chip share `DocumentTrust.tone`. Left to WP6/WP9: the "Transcribe again"
  action Android puts on the audio-changed and unreadable banners (it needs WP6's read-only gating and fresh
  transcription dialog), and moving these banners into WP9's `Banner`.
- Not done here: the provenance of the exported variant still says `{engine: cassini-ios, kind: user-edited}`; WP5's
  job provenance is not available yet.
