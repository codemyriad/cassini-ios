# WP14 (part) — Localization, accessibility, contrast, wide windows, state restoration

## Differences from Android

- **String check.** Android lint fails on missing translations; iOS has `scripts/check-strings.sh` (run by
  `scripts/test.sh fast` and `all`, and by `changed` when an app source or a catalog changed). It fails on an Italian value that is missing, `new`, `needs_review` or empty, on a plural
  without its `one`, `many` and `other` forms, on placeholders that differ from the English, on keys no source uses
  (stale), on strings the sources ask a table for that it lacks, and on literals outside any table. Keys are compared
  with `xcstringstool extract`, which cannot type an interpolation, so `%@` and `%lld` compare equal; a key in a
  ternary (`cond ? "a" : "b"`) is not seen by it, so the sources write such pairs as two `Text`s. The check reads the
  app's sources only (Cassini, CassiniShared, CassiniActivity); package text that reaches the screen is worded in the
  app instead: `RepositoryError` through `FailureReason` (Failures table), placeholder speakers through
  `NoteCopy.speakerLabel` (the Speakers sheet's rows included), version kinds through `SpeakersCopy.versionKind`. Package English that is not shown:
  `AudioError.errorDescription` (capture and playback failures reach the screen as banner codes, never as its text) and
  `LicenseTexts.modelSections` (section titles the notices file is split by; the notices are English legal text).
- **Stored text.** Transcript versions store a kind (`transcription`, `mergedSpeakers`, `editedPassages`, ...), named
  on screen from the Speakers table, instead of an English name; earlier notes map their English names to kinds when
  read (an unknown name is kept and shown as it is). A kind code a newer build wrote is kept as that code and written
  back under `kind`, and shown as "From a newer Cassini". Bookmarks (an iOS extra) need no default label; the screen
  says "Moment at 01:05" in the reader's language. Android has neither problem: its variants carry no display name.
  `Note.schemaVersion` stays 2: for builds from before this change, which require both fields, each version also
  stores its English `name` beside `kind` and an unlabelled bookmark stores "Marked moment", which this build reads
  back as no label. A rollback therefore still reads every note.
- **Speaker placeholders.** Notes store "Speaker N" (or "Voce N" from an Italian build) for an unnamed speaker, as
  Android does; the transcript, Name this speaker (title, header, merge list and confirmation), the suggestion card
  and the passage editor's picker name it "Speaker N" / "Voce N" in the reader's language.
- **Contrast.** `ContrastTests` follows Android's `ContrastTest` but has no documented ratio table to match: the iOS
  palette is the warm brand palette plus tone tints. It checks every pair a screen draws, with tone tints composited
  over the paper or card under them. Light `muted`, `ember` and `toneWarn` were darkened, white text sits on
  `emberFill` (a deeper ember in dark mode), and the draft's unsettled words use `faint` instead of muted at 60 %.
- **Accessibility audits.** Android runs the Accessibility Test Framework; iOS runs `performAccessibilityAudit()` on
  the same screens plus Recently Deleted and Saved voices, and the clipping audit at AX5 (in place of
  `LargeFontScaleTest`). The audit's contrast check and its Dynamic Type check at the default size are not used: they
  sample rendered pixels (Liquid Glass buttons, anti-aliased text) and flag standard text styles, with a different
  verdict on each run. Contrast is checked on the tokens instead, and text growth by the AX5 run. Filtered with
  reasons in `AuditFilter`: the system's bars and keyboard, the DEBUG launch marker, the Library row preview (two lines
  by design, as Android's `maxLines = 2`), and one text-clipping report without an element on a screen with a
  navigation bar (its title, which iOS shrinks beside the bar buttons; a second such report fails).
- **Capped bars.** The player and the capture bar stop growing at AX1 and show the Large Content Viewer, the iOS
  pattern for bars; Android keeps the skip digits' size the same way. When Import and Record do not fit side by side,
  Import becomes a round icon (Android `CaptureBar`), with no vertical stacking.
- **Wide windows.** One `ReadableWidth.content` of 560 pt (Android `MaxContentWidth`) for every screen, Settings and
  Saved voices included. In the iPad split view the detail column's list runs under the sidebar, so the margins are
  computed from the visible column. `WideScreenTests` checks the note, Recording, Model download, Saved voices,
  Settings, Recently Deleted and the Rename form on iPad in landscape. Android's `library` case has no iOS
  counterpart: on iPad the Library is the split view's sidebar, narrower than the cap; `transcribing` is the Note
  screen's processing mode, whose column the note case checks; iOS draws the dimming behind sheets and alerts itself, so `DialogLandscapeTest`'s scrim check
  becomes a check that the form stays in its band.
- **State restoration.** Android keeps sheets and dialogs with `rememberSaveable` and `NoteViewModel.saveOverlays`.
  iOS keeps the Note screen's sheet (Rename and Name this speaker with the text typed, Speakers, Versions, Document
  info, Edit passage) and its question (Start over?, Transcribe again?, the read-only explanation), and the Library's
  dialog (Rename with the title typed, Start over?, Transcribe again?) with the scene, as Recently Deleted and Saved
  voices already did. They come back once the note is read, unless what they were about is gone, the transcript is
  read-only for a sheet that changes it, the read-only reason no longer holds, or Transcribe again no longer makes a
  fresh document. Android restores its dialogs without these checks. What was kept is consumed on the screen's first
  appearance with its note: what cannot come back then is dropped, so it never opens by itself on a later visit.
  Android's Stop and move to Recently Deleted? is not a Note screen dialog on iOS (`trashStopConfirmation` on the root
  view) and is not kept. The rules (`SavedNoteOverlay`, `NoteOverlay`, `NoteDialog.restorable`,
  `SavedLibraryDialog`) are unit-tested. There is no UI test: XCUITest's `terminate()` after sending the app to the background discards the
  scene's saved state, so a relaunch never restores (tried in this package).
