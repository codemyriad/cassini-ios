# WP10 — Settings, model status, licenses: notes for the README and later work packages

## Differences from Android

- **App language.** Android has a Phone / English / Italiano segmented control (AppCompat locales). iOS sets an
  app's language in the Settings app, so the row shows the current language and opens Cassini's page there. Its
  footnote says the speech language is chosen separately: iOS asks for one (Apple's models are per language), where
  Android recognises any language automatically.
- **Sections.** App language, Transcription (speech language with "· Installed", Transcribe after recording or
  import), the notifications-off banner, On-device models, Speakers (identify speakers, name strong matches
  automatically, off by default), Privacy, Your library and About. Android has no Transcription, Speakers or Your
  library sections; they are iOS extras. The old iOS "Recording" section (format and capture quality, Microphone
  permissions) and the "Allow … downloads" switches are gone: consent comes from the model download screen, as on
  Android, and a missing model the user agreed to shows "Downloads with next transcription".
- **Model rows.** Speech recognition is Apple's assets for the chosen speech language: "Managed by iOS" instead of a
  size (iOS does not tell it before the download), and "Not available" when Apple offers no model for the language or
  device (iOS only). Telling speakers apart shows the pinned files' size. Recognising saved voices uses the same
  speaker models, so its row says "Comes with telling speakers apart" and always has their status. A running job's
  download (from `JobProgress`) and a standalone download show on the rows live (`ModelInstalls.statuses`; a speaker
  models download shows on both speaker rows). `ModelInstalls` reads the rows again when the screen opens, when the
  app comes back to it, when the speech language changes (a failed speech install counts only for the language it was
  for) and when a job's download ends, wherever Settings is. The Speech language picker's entries and their
  "· Installed" mark come from `Transcribing.speechLanguages()` through `SettingsModel.languageOptions`.
- **Privacy row names.** "Recently Deleted" (kept iOS naming) instead of Trash. The counts read "4 people",
  "2 notes", "None yet" and "Empty", as on Android.
- **Your library** counts only notes outside Recently Deleted, for both the recordings and the audio duration
  (`SettingsModel.totals(of:)`); before WP10 the duration counted Recently Deleted too.
- **About** reads the version from `CFBundleShortVersionString` (no hard-coded "0.1.0") and links "Source code and
  notices".
- **Copy.** Android's English with "device" for "phone" ("Transcription runs on this device. Audio never leaves it.",
  "— turns speech into searchable, timed text on your device.").
- **Source code and notices.** The rows are Cassini (GPLv3, a bundled copy of `LICENSE`), Third-party notices, Model
  notices, Where the models come from, Privacy and Source code on GitHub (`github.com/codemyriad/cassini-ios`).
  Android's Native libraries row is folded into Third-party notices (libopus, swift-opus, FluidAudio, fastcluster and
  VBx are all there) and there are no font rows, since iOS ships no fonts. The texts are bundled under
  `Cassini/Resources/Licenses/`: `Cassini-GPL-3.0.txt`, `ThirdPartyNotices.txt` (moved there) and `Privacy.txt`, the
  iOS privacy text in Android's structure. A row opens its text in a pushed pane (selectable; licences in small mono,
  the rest as paragraphs); the opened row is kept in scene storage, as Android keeps it in `SavedStateHandle`. The back
  label comes from the navigation bar, so `LicensesBackTo` has no port.
- **Speaker model install.** `SpeakerAnalyzer` no longer throws `busy`: an analysis that arrives during another waits
  its turn, and every request during an install joins it (`SpeakerModelInstaller`), so a second identify-speakers
  request during a download waits and succeeds. The install is FluidAudio's `ModelHub.download` of the revision
  FluidAudio pins (`df2625ac…`), checked file by file against the checked-in `SpeakerModelManifest.diarizer` (21 files,
  size and SHA-256, matching the revision's `provenance.json`) and the `.fluidaudio-revision` marker. A mismatch is
  `FILE_CHECK_FAILED` and the folder is removed for the next try. Before a download only what FluidAudio would keep
  wrongly is removed (it skips every file it finds): files with the wrong size or hash, or the whole folder when its
  marker names another revision. Finished files and FluidAudio's `.partial` files stay, so an interrupted install
  resumes. A request that arrives while a cancelled install's fetch is still unwinding waits for it to end and then
  starts its own, so one fetch at a time runs and nobody gets the cancelled install's `CancellationError`. The free
  space checked before the first byte is the files plus 32 MiB ("Free about N MB"); the model download screen asks
  for the same figure (`SpeakerAnalyzing.modelInstallBytes`), and keeps Apple's speech assets at the 512 MiB
  estimate. Errors are classified as `NO_CONNECTION`, `INTERRUPTED`, `NOT_ENOUGH_STORAGE`, `FILE_CHECK_FAILED` or
  `INSTALL`. The status is stored and refreshed at launch, when Settings opens and after installs; a failure stays
  until the next install. A request while the status is ready checks only the marker and the sizes; the full hash
  check runs on refresh.
- **Offline errors.** Android maps IO, HTTP and connection-reset errors to `NO_CONNECTION` when its `online()` check
  says the device is offline. iOS has no reachability check: URL Loading already reports an offline device as
  `notConnectedToInternet` (and `timedOut`, `cannotFindHost`, `dataNotAllowed`…), which map to `NO_CONNECTION`;
  `networkConnectionLost` and HTTP errors map to `INTERRUPTED`.
- **FluidAudio's offline switch.** `ModelHub.offlineMode` is process-wide. `ModelNetworkGate` keeps it on and turns it
  off only while at least one permitted download runs, counting them, so a request that joins or ends never turns it
  back on during another download (critique E.30). Analyses load the models with it on, so a damaged file fails the
  load instead of being downloaded again without consent.
- **Redirect allow-list.** FluidAudio's downloader builds its own `URLSession`s and exposes no session delegate, so
  Cassini cannot restrict redirects itself; `RedirectPolicyTest` has no port. Integrity rests on the pinned revision and
  the hash check of every file. `Privacy.txt` lists the hosts the downloads normally use (`huggingface.co`,
  `*.huggingface.co`, `*.hf.co`) and says that no redirect policy holds them there.
- **Speaker models as best effort.** As Android treats them as best-effort parts, a transcription whose speaker models
  fail to download still saves its words in one voice. A speakers-only job, which has nothing else to do, now ends with
  `JobFailure.download(x)` (part `.speakers`) or needs consent instead of succeeding silently.
- **Standalone download.** The model download screen's Download (no note) installs every part that is not ready, as
  Android's `startDownload()` does, whatever the Speakers switch says (`ModelPlan.plan`), one part after another
  (`ModelInstalls`). A request while one runs adds the parts it does not cover, which install after it, also during
  the refresh that closes the install; before WP10 only Apple's speech assets were installed and the speaker models
  waited for the first analysis.
- **Cancel.** As Android's `ModelInstallOwner.cancel()`, `ModelInstalls.cancel()` stops the standalone download: the
  part in flight is cancelled (`SpeakerModelInstaller.cancel()` ends the speaker models' install for every caller,
  a job's analysis included, which then saves its words in one voice; Apple's asset install is cancelled through its
  task) and the parts after it are dropped. A cancel is no failure, and an older failure does not show again. The
  partial files stay for the next install. A part asked for again during the install's closing refresh drops its
  earlier failure, so a retry that succeeds ends without a failure notice. `TranscriptionCoordinator.cancelDownload()`
  is Android's `ProcessingCoordinator.cancelDownload()` with its `Cancel.RESTORE`: while the running job's phase is
  downloading (also before its first progress, and a speaker models download during the run), the job stops and the
  note goes back to its state from before: paused by the user with its saved progress, else its job is removed
  ("Audio only" for a first Transcribe). `ProcessingStore.cancelDownload()` uses it, else cancels the standalone
  install, for the download notice's Cancel, which the notices work package wires. On iOS the paused notice is told
  only when the job stays paused. A job
  waiting on Apple's speech assets is not ended by it: iOS has no shared owner of that install, and AssetInventory
  shares the download itself.

## Android tests ported

- `SettingsViewModelTest`: all five (the app-language one as the row that opens the Settings app) in
  `CassiniEngineTests/SettingsModelTests`, plus the library totals.
- `ModelInstallOwnerTest`: `aJobJoiningTheStandaloneDownloadFetchesEachArtifactOnce`,
  `cancelEndsEveryWaitAndKeepsThePartFiles` (`ModelInstalls.cancel()` ends the standalone download and a job's
  analysis waiting on the same install, FluidAudio's partial files stay, and the row is Not downloaded again),
  `theInstallStopsWhenItsLastWaiterLeaves` (and the next install resumes the partial files),
  `aRequestRightAfterACancelWaitsForTheCancelledFetchToEnd`, `downloadErrorsAndProgressMapToTheModelStatus` in
  `CassiniInferenceTests/SpeakerModelInstallerTests`, and `aRequestForOtherPartsWaitsAndFetchesNothingTwice` with
  the standalone side of the first in `CassiniEngineTests/ModelInstallsTests`. `SpeakerAnalyzerQueueTests` checks
  that a second analysis waits for the first and succeeds, over an injected analysis.
- `ProcessingCoordinatorTest`: `cancelDuringTheDownloadOfAJobPutsTheNoteBackToItsStateFromBefore` in
  `CassiniEngineTests/TranscriptionCoordinatorTests`, with a download that starts during the run.
- `ModelInstallerTest`: `errorsMapToTheDownloadBanners` (FluidAudio, URL and file errors) and
  `notEnoughSpaceFailsSpeechBeforeTheFirstByte` (the speaker part).
- `LicensesViewModelTest`: `listsEveryRowAndOpensATextPane`, `sourceCodeOpensTheBrowserAndNoPane`,
  `theOpenPaneComesBackAfterProcessDeath` (`CassiniEngineTests/LicensesModelTests`) and
  `everyRowHasItsTextFromTheAssets` (`CassiniInferenceTests/LicenseAssetsTests`).
- `LicenseAssetsTest`: the bundled GPL equals `LICENSE`, the privacy text lists every download host, and the notices
  name every package in `Package.resolved` and libopus (iOS has no native-dependency manifest or font licences).
- `SettingsBehaviourTest` licence rows: `CassiniUITests/SettingsFlowTests`, with the model rows, the banner, the counts,
  the bundle version and the standalone download from a Not downloaded row.

## Interface changes (for the integrator)

- `SpeakerAnalyzing` gains `refreshModelStatus()`, `installModels(progress:)` and `cancelModelInstall()`, and `SpeakerAnalysisError`
  (`needsConsent`, `download(_:requiredFreeBytes:)`) is what its analysis and install throw. `FakeAnalyzer` implements
  them in `Fakes+WP10.swift`.
- `SpeakerAnalyzing` also gains `modelInstallBytes`, and `Transcribing` gains `speechLanguages()` (with
  `SpeechLanguage`); `FakeTranscriber` implements it in `Fakes+WP10.swift`.
- `SpeakerAnalyzer.init(directory:storage:network:)` takes a `StorageProbe`; `modelsAvailable` is gone (use
  `modelStatus()`). `SpeakerAnalyzer.init(installer:network:analysis:)` takes the analysis step, for tests.
  `SpeakerModelManifest.Check` has `.incomplete` (resumable) besides `.mismatch` (wrong files).
- `ModelDownloadPorts.plan()` is `plan(for: noteID)`; `ModelPlan` is built by `ModelPlan.plan(...)` or with explicit
  bytes (`installBytes(_:)` is gone; `speechInstallBytes` stays). `SettingsPorts` gains `speechLanguages()`.
  `ModelInstalls.init` takes the `JobProgress` (`job:`) and has `statuses` and `cancel()`; `SpeakerModelInstaller`
  has `cancel()`; `TranscriptionCoordinator` has `cancelDownload()`, which `ProcessingStore.cancelDownload()` uses. `CassiniInferenceTests` also depends on
  CassiniEngineTesting.
- `ModelInstalls.swift` and `JobProgress+Models.swift` live in `CassiniEngine/Installs/`: the `Models/` rule in
  `.gitignore` (for weights) matches any folder named `Models`. New in CassiniInference: `SpeakerModelManifest`, `SpeakerModelInstaller`, `ModelNetworkGate`.
- New in CassiniEngine: `ModelInstalls` (stored model status and standalone installs), `JobProgress.modelDownload`,
  `ModelRows`/`ModelRow`/`ModelRowStatus`/`ModelSize`, `SettingsModel`/`SettingsPorts`, `LicenseEntry`,
  `LicenseTexts`, `LicensesModel`, `sourceCodeURL`.
- `ProcessingStore`: `installSpeechModel(language:)` and `speechInstall` are replaced by `models: ModelInstalls`
  (its `download` goes to `NoticeFacts.download`); its init takes `models:` instead of `transcriber:` and `clock:`.
  `ModelDownloadAdapter.downloadModels` installs every part it is given.
- `AppGraph` has `settingsPorts` (`SettingsAdapter`, which also takes the transcriber) in the environment and
  refreshes the model status after launch.
- `TranscriptionJob`'s speaker step takes whether the models are required (speakers-only jobs).
- `Package.swift`: `CassiniInferenceTests` also depends on CassiniEngine and CassiniNotebook.
- Strings: the `Settings` table (`Cassini/Resources/Strings/Settings.xcstrings`), English and Italian.
- UI tests: Licenses' title is now "Source code and notices" (`ModelDownloadFlowTests` follows), and the Settings smoke
  test checks the Transcribe switch instead of the removed download switch. The Privacy rows read as one element with
  their count, so they carry the identifiers `savedVoicesRow` and `recentlyDeletedRow` (`SpeakerNamingFlowTests` uses
  the first).
