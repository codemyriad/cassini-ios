# Real ZIP writer fixtures

These archives contain synthetic English text, not audio, despite their `.opus` names. Each newly generated archive
contains `Notes/Meeting.opus` and `Notes/café.opus`, each containing exactly `English ZIP sample.\n` (20 bytes,
including the newline). They are Core ZIP reader fixtures, not valid inputs to an audio decoder.

`writer-manifest.json` records the tool identities, official download source, input timestamps, exact archive hashes,
expected plaintext, and inspected local/central header facts. Archive bytes were copied directly from writer output
and were never patched, re-encoded, repacked, or normalized. The commands below ran from the owned scratch `inputs`
directory; `Notes` contained the two source files, with file and directory mtime set to `2000-01-01T00:00:00Z`.
Recorded ZIP hashes identify the committed outputs; filesystem creation/access timestamps can affect regeneration.

## Apple ditto

```sh
/usr/bin/ditto -c -k --sequesterRsrc --keepParent Notes ../output/ditto-macos-unicode.zip
```

Generated on macOS 27.0.1, build 26A434, arm64. The receipt identifies the system `/usr/bin/ditto` by SHA-256;
no separate ditto version is asserted. `ditto-macos-unicode.zip` is 490 bytes, SHA-256
`587fba0bb9cd41bf8eaf21b8010e658e9a5a38a1ba741af78386ce7223bdd2b1`.
Its Unicode name is UTF-8 with local and central flags `0x0008` (bit 11 unset). Its Unix `0x5855` extras appear
in both headers. This is a real ditto command-line capture, not a Finder GUI capture.

## Official 7-Zip console writer

```sh
../sevenzip-26.06/7zz a -tzip ../output/sevenzip-26.06-macos-unicode.zip Notes
```

The [official download page](https://www.7-zip.org/download.html) linked the macOS arm64 console package for
[7-Zip 26.06](https://github.com/ip7z/7zip/releases/tag/26.06), released 2026-11-06:
[7z2606-mac.tar.xz](https://github.com/ip7z/7zip/releases/download/26.06/7z2606-mac.tar.xz).
The downloaded package SHA-256 was
`b6f17920b4240940461dac8ef4009891881ac44d2a5ead625ede2ec8472185dd`, matching the official GitHub asset's digest.
It was unpacked and run only in the owned external scratch directory, without a global installation. The receipt
also records the extracted executable's hash and its `7-Zip (z) 26.06 (arm64)` version output.

`sevenzip-26.06-macos-unicode.zip` is 478 bytes, SHA-256
`713fdbac056fc7033971d82af0ff28335244167a74845f93496475d52d0b9b3d`.
Its Unicode name has matching local/central flags `0x0800`; ASCII entries have flags zero. The central directory
has `0x000a` timestamp extras absent from local headers. Those are not Unicode-path annotations.

## Header evidence and limits

Python inspected the newly generated bytes without changing the archives. Local and central raw names, decoded
names and compression methods agree; encryption flags and AES extras are absent; paths are safe. Both archives
have no `0x7075` Unicode-path annotation in either header, so their annotation presence/value agrees. Plaintext and
CRC checks were verified through Python's independent ZIP reader. This receipt does not claim a Swift test pass.

These samples establish compatibility facts for Apple ditto and the official macOS 7-Zip console writer. They do
not establish Finder GUI, Windows Explorer, Windows 7-Zip, Android Files, or a real writer emitting `0x7075` on only
one side. Keep the existing strict local/central Unicode-annotation checks; these fixtures require no relaxation.
