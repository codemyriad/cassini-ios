# Working in this repository

- Sibling of `../cassini-android` (branch `rebuild`); port behaviour from there and keep the same tests. Public format references live in `../cassini-format`, the desktop pipeline in `../gocassini`. Document differences from Android in the README. Where iOS and Android disagree, Android's behaviour wins unless the difference is an iOS-only extra or a platform constraint.
- Toolchain: Swift 6.2+ tools, Swift 6 language mode, iOS 18.0 deployment target (keep iOS 26 APIs behind `#available` and keep iOS 26 behaviour unchanged; rules take the OS facts as values, `PlatformFacts` and the Whistle OS and CPU facts in `WhistleCapability`, see `docs/ios18.md`), Xcode 26 or newer (developed with Xcode 27). Build and test locally on macOS; `scripts/test-remote.sh` runs the same steps on another Mac named by `CASSINI_MAC`.
- Generate the Xcode project with `xcodegen generate`; never commit `Cassini.xcodeproj`.
- Keep pure rules (anything Android unit-tests) in Swift packages so `swift test` covers them; the app target holds composition, adapters and views only.
- Keep model weights, recordings, build outputs and generated Xcode projects out of commits.
- Testing: `scripts/test.sh` (tiers in its header and the README). While iterating, run a subset: `scripts/test.sh changed` (what the diff against origin/main touches; fetch first), `scripts/test.sh fast`, or `scripts/test.sh ui -only-testing:CassiniUITests/<Class>[/<method>]`. Before finishing, push the branch and run `CASSINI_POST_STATUS=1 scripts/test.sh all` once, green: it posts the result on the pushed commit as the status `drmeyers/test-all`, which a merge looks for. Never delete another worktree's simulator clones; `scripts/test.sh clean` removes only your own. After a PR merges: `scripts/test.sh clean` in its worktree, then `git worktree remove <path>` and `git worktree prune` (a heavy run also deletes, once shut down, the clones of worktrees that are gone).
- UI tests launch through `launchAndWait()`, which relaunches inside the running app when it can; pass `fresh: true` (or terminate first) when a test needs a new process. Wait with the polling helpers in `CassiniUITests/Waiting.swift`, never with sleeps; they wait at least 15 s, so check that something stays off the screen with `staysAbsent(for:)`, not a negated wait; check a condition before each swipe rather than swiping a fixed number of times. Tap an item of a context or pull-down menu with `tapWhenSettled()`: system menus still animate in.
